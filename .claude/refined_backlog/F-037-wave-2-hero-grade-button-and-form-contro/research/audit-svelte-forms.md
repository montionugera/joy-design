## Summary
Files audited: 21 Svelte form and interactive components in packages/svelte/src/lib (Button, Input, InputNumber, Select, Checkbox, Switch, RadioGroup, Slider, Rate, Segmented, Form, FormItem, DatePicker, TimePicker, DateRangePicker, Mentions, Upload, TreeSelect, Cascader, Transfer, MarkdownEditor), corresponding CSS in packages/tokens/build.js and dist/theme.css, and twin implementations in packages/react/src.
Issue count by severity: 115 issues total (P0: 24 blocks production / P1: 67 visibly sloppy / P2: 24 polish).
Verdict: Fails production grade in the product register due to widespread foreign Tailwind slate/purple palette contamination, complete dark mode omissions for core inputs (Checkbox, Switch, Radio, Rate, Select), mobile viewport horizontal overflow in complex widgets (Cascader, Transfer, DateRangePicker, MarkdownEditor), missing iOS font-size scaling (14px triggering auto-zoom), broken overlay architecture (un-portalized popups clipping in overflow containers, missing Escape/click-outside), and universal failure to satisfy the 44px mobile touch target standard.

## Systemic patterns
- **Unauthorized Tailwind slate and purple palette infection**: Instead of brand anchors (`--navy-500: #14253e`, `--gold-400: #c49a3a`, `--ink-500: #1f1c13`), form components systematically fall back to Tailwind purple (`#7c3aed`, `#6d28d9`, `#8b5cf6`, `#a855f7`) on focus rings, tracks, and checked states, while dark themes hardcode raw cool slate (`#0f172a`, `#1e293b`, `#334155`, `#cbd5e1`) rather than brand navy tints.
- **Critical dark mode omissions across foundational inputs**: Core form elements—including `Checkbox`, `Switch`, `RadioGroup`, `Rate`, and `Select` in `build.js`—define zero `[data-theme="dark"]` selectors, causing them to render with hardcoded `#ffffff` backgrounds, low-contrast borders, and invisible unselected icons on dark surfaces.
- **Mobile touch target failure (<44×44px)**: Almost every interactive control—including Button (sm: 28px, md: 38px), Switch (24px), Checkbox (18px), Radio (18px), Slider handle (18px), Rate star (20px), Segmented item (28px), DatePicker (36px), TimePicker cells (26px), Upload remove button (16px), and MarkdownEditor toolbar buttons (28px)—fails the WCAG 2.2 AA and brand touch target minimum of 44×44 CSS px.
- **Mobile iOS viewport auto-zoom defect**: Inputs in `Input`, `DatePicker`, and `Mentions` set fixed `font-size: 0.875rem` (14px), triggering iOS Safari to automatically zoom the mobile viewport upon focus and breaking application responsiveness.
- **Multi-column widgets causing severe mobile horizontal overflow**: `Cascader` (multi-column menus ≥ 420px), `Transfer` (dual lists + operations flex row ≥ 400px), `DateRangePicker` (dual inline date pickers ≥ 360px), and `MarkdownEditor` (50/50 split pane) lack mobile media queries and overflow a 375px viewport.
- **Fragile overlay architecture & clipping defects**: Dropdowns and popups in `TimePicker`, `Mentions`, `TreeSelect`, and `Cascader` are rendered inline with `position: absolute` and arbitrary `z-index` (e.g. 1000) rather than using a portal/teleport mechanism, causing them to be clipped by any parent container with `overflow: hidden` or `overflow: auto`.
- **Missing overlay keyboard and dismissal contracts**: Overlays across `TimePicker`, `Mentions`, `TreeSelect`, and `Cascader` lack keyboard traps, Escape key listeners, and reliable click-outside dismissals (e.g. `Mentions` relies on a 200ms `onblur` timer race condition).
- **Hardcoded Navy card leakage in light mode**: High-level complex widgets (`TreeSelect`, `Cascader`, `MarkdownEditor`) hardcode Navy dark fallbacks (`var(--joy-surface-card, #14253e)` and `var(--joy-text-primary, #f8f3e8)`) in inline styles, causing them to render dark on light surfaces when CSS custom properties are not locally re-scoped.
- **Complete absence of reduced-motion support**: CSS transitions and animations across `Button`, `Input`, `Switch`, `Slider`, `DatePicker`, `Upload`, and `Segmented` omit `@media (prefers-reduced-motion: reduce)` overrides, failing accessibility guidelines for motion-sensitive users.
- **Component property and class name hallucinations**: `Transfer` references a non-existent `joy-button--primary` class instead of `joy-button--solid`, `FormItem` hardcodes legacy Chinese font `SimSun` for asterisks, and `DateRangePicker` injects a prohibited Unicode right arrow (`→`).
