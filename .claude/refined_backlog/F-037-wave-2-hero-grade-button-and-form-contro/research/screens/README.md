## D3.7 final taste verdict (button-*.png, post-D3.6 re-shoot)

Third and final `impeccable` pass on the current `button-{light,dark}-{375x812,1280x800}.png` (the two earlier passes both returned FIX; D3.6 fixed those findings in commit `791a969`). Verdict: **FIX** — one regression found and fixed:

- 6/7 checks PASS: 375px topbar no longer overlaps the h1; dark canvas dot-grid restored; size segmented control doesn't wrap at 375px; no doubled spaces in button labels; REACT 19 badge retoned off bright blue; general taste coherent in both themes.
- 1/7 FIX: the state-matrix **focus** tile was still byte-identical to default (pixel-sampled), even though **hover** was correctly distinct. Root cause: `.joy-button--demo-focus` (single-class selector, specificity 0,1,0) and `.joy-button--solid` (also 0,1,0, declared later in `packages/tokens/build.js`) had equal specificity, so the solid variant's own `box-shadow` silently clobbered the focus ring's `box-shadow` — the same class of bug as the earlier InputNumber modifier-ordering defect. Fixed by making the selector compound (`.joy-button.joy-button--demo-focus`, specificity 0,2,0) so it out-specifies every single-class variant rule regardless of source order, matching how the real `.joy-button:focus-visible` selector already worked. Re-verified pixel-level after the fix and re-shoot: the focus tile now shows a distinct gold outline + halo ring in both light and dark, at both viewports. Regression-guarded by a new assertion in `packages/tokens/test/wave-2.test.js`.
