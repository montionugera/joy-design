## Spec ambiguities resolved (assumptions)

1. **Lanes are twin pairs, sequential.** Unlike F-038 (Svelte lanes vs React lanes), each landing lane edits the Svelte file, the React file and the `build.js` block of the same components in one worker, because the files are small (1.9k lines for all 28) and twin drift is the main risk. Sequential landing order L1 -> L2 -> L3 -> L4 -> L5 avoids `build.js` conflicts.
2. **Primary CTA reuses the Wave 2 `joy-button--solid` depth** (2-stop same-hue gradient, inner top highlight, gold-tinted `--joy-elevation-accent-*`, loading spinner, `--joy-focus-ring` style ring, `--joy-control-height-lg` via `joy-button--lg`). L1 adds only what is hero-specific: hover lift of 1px (spec) scoped to `.joy-hero` and `.joy-cta-section` (the Wave 2 base lifts 2px; the base is not changed), full width under 480px, `primaryLoading`/`primaryDisabled`/`primaryHref` props. No new tokens.
3. **Secondary CTA** is `joy-button--outline` with `--joy-border-strong` and `--joy-text-primary` on light; inside the dark CTA band it uses a cream-tinted text token (`--joy-text-primary` in dark theme is already cream-tinted; L1 verifies and records the computed ratio). The `.joy-button--glass` class and its CSS are deleted; nothing may reference it.
4. **`titleEmphasis`** renders `<span class="joy-hero__title-emphasis">` with `color: var(--joy-accent-text)`, a solid colour, not a gradient (>= 4.5:1 in both themes, asserted).
5. **Mobile nav below 768px uses `@media (max-width: 767px)`**, not container queries: a container-query root would make `position: fixed` drawers contain to the landing root. Consequence, recorded as a known deviation: the hub simulator's "Mobile (375px)" frame narrows the frame but media queries follow the real viewport; the acceptance contract and screenshots use a real 375px viewport. Filed as a backlog idea (Wave 5 owns hub chrome).
6. **Hub landing view = `#view-landing-preview` (full-page simulator) and `#view-landing-blocks` (component blocks)**; the contract and screenshots target `#landing-preview` (the page that contains the header, hero, CTA, footer) and screenshot `#landing-blocks` as well.
7. **Coverage universe = 168 IDs:** SVL-001..090 (90) plus 78 RXF rows (the 77 Wave 2 landing deferrals + RXF-002). RXF-136/137 (hero button lift and focus ring) were closed by Wave 2 and are not in this universe.
8. **Deferred by design (pre-decided, confirm in lane):** SVL-032 style feature requests (e.g. PricingCard extra props) are deferred only when the lane shows the row is a new feature, not a defect, with the reason written in the coverage table.
